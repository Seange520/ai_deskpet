# R1 抢修竖切设计：晴光街 15 分钟委托（v1）

**版本**：v1 / 2026-11-10
**目标**：用最小成本验证 V3「抢修危机」核心循环的爽感与教学兼容性，作为 R1 的 playable 竖切。
**依据**：`CORE_GAMEPLAY_V3_REGISTRATION_WAR.md`（抢修/校验位/校筑）、`GAME_ADAPTATION_V1.md`（ch01 抢修教学局）、`BROAD_APPEAL_AND_DUAL_TRACK_V1.md`（体验轨/校验轨）、`R1_A2_ASSET_BRIEF_V1.md`。

## 1. 验收目标（数字化）

| 指标 | 目标 |
|---|---|
| 单局时长 | 12–18 分钟 |
| 首屏到可操作 | ≤6s（桌面 1080p） |
| 帧率 | 1080p ≥60fps（RTX 5060 基准）；移动 720p ≥30fps |
| 爽感采样 | 10 名试玩 ≥7/10「想再来一局」；≥7/10「操作手感清楚」 |
| 教学采样 | 能复述「先断电、再测量、后接线」≥8/10 |
| 双轨通过 | 体验轨（不测量也能通）与校验轨（测量拿高分）都可达 |

## 2. 循环

```
接单（塔/贺菲派单）→ 空降/走进故障街区 → 观察现象（灯闪/焦味/火花）
→ 断电隔离（安全动作）→ 定位故障段（3–5 个嫌疑点，可暴力试错）
→ 抢修（换保险/紧接头/换线/合闸；有「快修」与「正修」）
→ 通电验证（灯亮/表读数正确）→ 结单评分 → 街区变化（灯亮、店开门、NPC 一句）
→ 回枢纽接下一单（共 3 单，第 3 单升级为「带压抢修」）
```

## 3. 单局结构（15 分钟）

| 分钟 | 内容 | 教学点 | 爽感点 |
|---|---|---|---|
| 0–2 | 接单 + 步行/小跑进街，远景灯带熄灭 | 任务简报 | 城市尺度、脚步声、冷启动 |
| 2–4 | 第一处故障：整条街闪灯；观察→断电 | 断电挂牌、验电 | 拉闸的「咔」+灯灭+音效 |
| 4–8 | 定位：3 个嫌疑点（表箱/接头/灯座），可用试错 | 通断档、串联回路 | 火花/短路声、灯闪节奏 |
| 8–11 | 抢修：换保险/压接/缠绝缘，操作小游戏 | 保险匹配、压接工艺 | 手部动作+工具反馈+「一次到位」判定 |
| 11–13 | 合闸验证：读数正确才算过；「快修」可能复燃 | 电压/电流读数 | 合闸瞬间全街亮起+音乐上扬 |
| 13–15 | 结单：评分（速度/正确/证据）→ NPC 反馈 → 街区变化 | 证据链 | 排名/称号/外观货币 |

## 4. 两条轨

- **体验轨（人人可通）**：允许试错、提示多、抢修小游戏有容错；评分上限 70。
- **校验轨（专业深挖）**：必须测量/记录/判断；评分上限 100；解锁「校验位」与图纸。
- 两轨共用同一局与同一世界，不分开做内容。

## 5. 技术范围（R1 最小）

- 场景：复用/改造现有街景（P10），新增 3 个可交互嫌疑点（表箱/接头/灯座）+ 1 个合闸点。
- 状态机：`idle → briefed → powered → isolated → located → repaired → verified → scored`。
- 交互：E 键检定/长按操作；仪表读数面板（复用现有 HUD）。
- 评分：`score = 正确性40 + 证据30 + 时间20 + 风格10`。
- 失败：复燃（快修未验证）→ 二次断电，扣分但不结束；三次失败本单重开。
- 不做：多人、空页、校筑建造（留 R2/R3）。

## 6. 美术要求

- 晴光街五件套（`R1_A2_ASSET_BRIEF_V1.md`）+ 现有街景混用；纸/黄铜 UI 沿用 `visual-paper.css`。
- 光照：暖傍晚 + 灯亮前后对比；合闸瞬间加 bloom + 粒子。

## 7. 交付物（R1）

- `?mission=r1` 可玩灰盒（3 单，含一条安全违规失败分支）。
- 1 段 60–90s 录屏 + 10 人试玩问卷结果。
- 性能报告（1080p 桌面 / 720p 移动模拟）。
- 双端评审记录（设计端 6 问 + 客户端 6 问）。

## 8. 验收口径

- 设计端：循环是否清楚、爽点是否落位、教学是否「藏而不丢」。
- 客户端：操作是否跟手、失败是否可理解、性能是否达标、bug 是否阻断。
- 通过线：双端各 ≥7.5/10；否则回到对应环节（关卡/手感/性能）修。
