## 2. 四路线对比

| 维度     | 经典方块桌宠             | 迷你四足机器狗               | 履带 / 麦轮小车            | 球形自平衡机器人           |
| -------- | ------------------------ | ---------------------------- | -------------------------- | -------------------------- |
| 难度     | ⭐                       | ⭐⭐⭐                       | ⭐⭐                       | ⭐⭐⭐                     |
| 核心硬件 | ESP32-S3 · 屏幕 · 麦克风 | ESP32-S3 · 8×SG90 · 独立供电 | ESP32-S3 · L298N · 底盘    | ESP32-S3 · MPU6050 · 球壳  |
| 知识重点 | GPIO · 3.3V · 共地       | 舵机驱动 · 压降 · PWM        | H 桥 · 方向控制 · 电机供电 | I²C · 姿态估计 · 控制入门  |
| 代码实验 | 表情 / 眨眼 / 主题       | 关节角度                     | 正转 / 反转 / 停止              | 加速度 / 角速度 / 静态姿态 |
| 典型错误 | 电源接反                 | 舵机共地缺失、压降复位       | 带电换向、ENA 悬空         | 混淆 I²C 与 I²S、轴向误读  |
| 适合人群 | 零基础入门               | 想挑战机电结构               | 想做移动机器人             | 对控制算法感兴趣           |

> 四条路线共用同一套「三关 + 奖励 + 成就」框架，换路线不换学习方式，降低认知负担。

## 3. 当前实现的取舍

| 选择 | 为什么这样做 | 代价与限制 |
| --- | --- | --- |
| 浏览器内虚拟练习 | 不必先备齐硬件就能试交互、整理知识点 | 不模拟真实电路，不能替代实体实验 |
| CSS / SVG 的 2.5D 拆解 | 可以沿用前端工具做出部件层次 | 不是可任意观察的 3D 模型，后续考虑 Three.js / React Three Fiber |
| 预设参数驱动代码与预览 | 先打通参数变化到可见反馈的路径 | 还不能自由编写、编译和执行代码 |
| 本地状态与 Mock 榜单 | 无需账号后端，能集中练习前端状态管理 | 不跨设备同步，不是真实多人排名 |
| 数据配置共用组件 | 物料、引脚和拆解规则容易一起维护 | 新传感器或行为通常仍需要实现专属组件 |

## 4. 维护时要守住的边界

1. **积分同源**：XP、徽章、排名和进度条从同一完成状态推导，避免重复奖励与状态漂移。
2. **反馈来自操作**：音效、Toast 和桌宠气泡按事件更新，刷新不重播旧反馈。
3. **交互可回归**：接线、拆解和降级路径保留测试，新增元件时同步验证原有路线。
4. **明确模拟范围**：示例引脚、价格、模拟 IDE 与静态姿态估计都应说明限制，不能当作可直接制造的方案。
5. **计划与能力分开**：代码沙盒、3D 模型、Web Serial 通信和故障关卡仍是后续方向，详见 [README Roadmap](../README.md#roadmap)。

待补充：真实设备联调记录、不同设备的性能数据，以及同好试用中的具体反馈。目前没有证据说明已提升学习完成率。
