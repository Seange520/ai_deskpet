# SparkMate · 项目想法与学习方向

> 一个从「我想学会做 AI 硬件桌宠」开始的浏览器教学实验。当前仍是 Testing / 开发中，先记录所学，再慢慢补齐真实硬件链路。

配套阅读：[README](../README.md) · [技术架构](architecture.md) · [功能矩阵](feature-list.md)

## 为什么做

最开始只是给自己搭一个测试网页：把零散的硬件资料、物料用途和接线笔记放在一起，学到哪里就试着实现一点。遇到结构看不清、引脚记不住的问题，就尝试用拆解和接线交互把它们表达出来。

后来开始好奇不同形态的桌宠怎么做，于是加了四足、小车、球形路线。音效、成就和常驻伙伴也是迭代中冒出来的点子，希望让反复练习没有那么枯燥。现在的功能是这些小实验累积的结果，不是完整制造方案。

## 开发中学到的事

- **配置和行为需要分开看**：共用物料与配对规则能减少重复，但新实验仍需要自己的预览与逻辑。
- **积分最好由完成状态推导**：保持幂等，比在各个按钮里累加 XP 更容易处理重载、切路和旧记录迁移。
- **反馈要由事件触发**：音效与 Toast 不应跟着每次重渲染播放；存储、音频不可用时也要能继续练习。
- **交互需要可验证**：保留鼠标、键盘、触屏和减少动画的回归检查；页面看起来能动，还不够说明它可靠。

已有验证记录：生产构建通过，44 项 Playwright E2E 通过；质检为 5 PASS / 1 WARN / 0 FAIL。唯一 WARN 是路线采用数据驱动注册，没有独立 routes/ 入口。这些是最近一次验证结果，不是实体硬件或教学效果的认证。

## 接下来想试

- [ ] 评估 Monaco Editor 等代码编辑器与受限执行沙盒，让自己写的代码能驱动桌宠预览。
- [ ] 尝试 Three.js / React Three Fiber，把现有 2D / 2.5D 图换成可探索的 3D 模型。
- [ ] 用 Web Serial API 做一个网页通过 USB 与真实 ESP32 通信的小实验。
- [ ] 增加硬件元件、故障排查练习和对应的学习笔记。
- [ ] 补齐具体型号、BOM、固件与实际测试记录，再讨论实体整机能力。

这些方向还在探索，优先级会随学习进度调整，尚无固定交付时间。
